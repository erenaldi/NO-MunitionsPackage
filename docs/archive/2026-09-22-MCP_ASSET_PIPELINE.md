## Publish contract

1. Keep each `.blend` master, source revision identity, multi-view reviews, and publish manifest in this repository when the asset work begins. Ordinary Blender saves remain local. Record shell/interface owners separately, plus scale, axes, material/group names, pivots, mount locations and separation joint datums.
2. Approve the silhouette and final look per `ASSET_DESIGN_WORKFLOW.md`. The explicit `/publish-asset` command presents a visual/dimensional diff and waits for user approval before any cloud or engine promotion.
3. Validate the candidate export. Onshape accepts STL as a source format, but its mesh is a reference, not editable feature history. The configured `onshape_upload_mesh_reference` tool requires a target document/workspace and an STL inside this repository; supply the existing blob element id on a later revision. Inspect translation state and the actual element in Onshape. Native Onshape mount and stage-joint features remain editable and must pass a fit check after reference changes.
4. Import the approved visual groups and Onshape-derived mechanical pieces into the selected Unity Editor. Verify import scale, bounds, materials, render/collision groups, prefab hierarchy, compilation, and existing Blueprinter/runtime components. If either destination fails, leave the last approved revision in effect and record partial state; cross-app writes cannot be rolled back atomically.
5. Only after both destination checks pass may the manifest mark a new revision promoted. In-game proving-ground flight and staged effects are a separate runtime acceptance gate, with player captures/logs when the flight cannot be automated.

An asset's publish manifest should identify the `.blend` path and source hash, approval packet/hash, unit/axis/pivot contract, mesh groups and exported-file hashes, Onshape document/workspace/reference-blob/native-interface ids, Unity project/source asset/prefab paths, and per-destination `pending | verified | failed` state. Record the last promoted revision separately from a candidate and its partial results; a retry must inspect the existing blob and Unity import before issuing another write. Keep credentials and downloaded game-derived source assets out of the manifest.
