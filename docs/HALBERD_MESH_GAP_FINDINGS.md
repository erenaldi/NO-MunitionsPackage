# Halberd intake mesh gap — diagnosis and native tessellator repair

2026-09-14. **Resolved in the locally rebuilt cadgen 0.5.0 runtime.** Native
STEP preview and native GLB export now retain closed intake topology. The OCCT
GLBs remain useful independent review evidence, but are no longer the required
workaround.

## Evidence

- User reported seeing through the intake surface in CAD Viewer.
- `cadgen step inspect validate Halberd_Shoulder_Hybrid.step --every-placement`
  passes: 19 occurrences, 9 prototypes, zero failures.
- Independent OpenCascade tessellation of every source part at 0.12 mm / 0.12 rad
  produces closed, consistently wound, positive-volume meshes.
- The cadgen mesh-export engine uses the same JavaScript surface
  tessellator as the STEP viewport (`cadgen/_internal/mesh_export.py:46-62`).
- Exporting an isolated body through that engine reproduces open mesh boundaries
  in the intake region in the old runtime, despite the closed BREP. The unchanged
  acceptance checker now passes this path; `Halberd_Hybrid_Mesh_Checks.json` is
  the current acceptance report.

## Source-side attempts

The ellipse sections use four exact arc quadrants instead of one periodic edge.
That source-side change reduced the old isolated viewer-mesh boundary count from
1621 to 554 but did not solve the defect; additional axial partitioning made it
worse and was reverted. No holes were hidden with double-sided rendering and no
geometry tests were weakened.

The defect was in `C:\Users\erena\Code\text-to-cad`: the JavaScript tessellator
used the visual chord tolerance to decide whether short open edges were closed
and whether distinct corner endpoints were identical. It now uses a separate
geometric tolerance (`max(scale * 1e-7, 1e-9)`) for topology while retaining the
visual tolerance for boundary resampling. Final float32 zero-area triangles are
discarded, and STEP-derived GLB export preserves exact tessellator coordinate
identity instead of applying the former five-decimal metre weld. Tessellation
cache version 2 prevents stale version-1 meshes from being reused.

The repair also resolves `CADGEN_CACHE_DIR` to an absolute path consistently on
Windows and makes runtime bundling portable under Git Bash. Source branch:
`fix/halberd-trimmed-face-tessellation` (based on `c222e5d`). The working tree
contains unrelated concurrent changes, so these paths must be reviewed and
committed selectively. The installed runtime backup is
`C:\Users\erena\AppData\Local\Temp\opencode\cadgen-mesher-backup-20260914`.

Reproduction (from `cad/`, using the cadgen venv):

1. `python generate_halberd_body_audit.py`
2. `cadgen glb build Halberd_Hybrid_BodyAudit.step Halberd_Hybrid_BodyAudit.glb`
